Bit of a comment answer, because we need a lot more information.

Resource semaphore isn't typically something you troubleshoot by looking at one query plan.

It's the result of a bunch of queries (or sometimes a bunch of the same query) asking for and getting memory, while other queries are waiting for them to finish and release it.

Since you're on a version of SQL Server reporting CXCONSUMER waits, head on over here: http://firstresponderkit.org (http://firstresponderkit.org) -- it's the repo for the open source scripts my company writes.

You can grab them all, but to start with you'll need `sp_Blitz`, and `sp_BlitzCache`.

Run this command, and update your question with the results:

`EXEC sp_Blitz @OutputType = 'MARKDOWN', @CheckServerInfo = 1;`

Next, run this:

`EXEC sp_BlitzCache @SortOrder = 'memory grant';`

And paste the plans (http://pastetheplan.com) for the top couple/few queries so you can update your question to share them.

But fair warning: if you're hitting resource semaphore waits, there's a good chance your plan cache has cleared out plans for the offending queries already.

```sql
SELECT
    EventTime,
    record.value('(/Record/ResourceMonitor/Notification)[1]', 'varchar(max)') AS [Type],
    record.value('(/Record/ResourceMonitor/IndicatorsProcess)[1]', 'int') AS [IndicatorsProcess],
    record.value('(/Record/ResourceMonitor/IndicatorsSystem)[1]', 'int') AS [IndicatorsSystem],
    record.value('(/Record/MemoryRecord/AvailablePhysicalMemory)[1]', 'bigint') AS [Avail Phys Mem, Kb],
    record.value('(/Record/MemoryRecord/AvailableVirtualAddressSpace)[1]', 'bigint') AS [Avail VAS, Kb]
FROM (
    SELECT
        DATEADD(ss, (-1 * ((cpu_ticks / CONVERT(float, (cpu_ticks / ms_ticks))) - [timestamp]) / 1000), GETDATE()) AS EventTime,
        CONVERT(xml, record) AS record
    FROM sys.dm_os_ring_buffers
    CROSS JOIN sys.dm_os_sys_info
    WHERE ring_buffer_type = 'RING_BUFFER_RESOURCE_MONITOR'
) AS tab
ORDER BY EventTime DESC;

SELECT TOP 1 creation_time
FROM sys.dm_exec_query_stats WITH (NOLOCK)
ORDER BY creation_time;
```
